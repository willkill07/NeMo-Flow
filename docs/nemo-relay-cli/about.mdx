Use the `nemo-relay` CLI to enroll local Claude Code/Desktop, Codex, and Hermes
clients in one persistent NeMo Relay proxy for your OS user account. The proxy
combines native lifecycle hooks with managed Anthropic and OpenAI provider
traffic so Relay can apply observability, guardrails, and interceptors without
launching the agent through a wrapper.

The integration covers local GUI, CLI, and background clients that use the
enrolled user configuration. Remote and cloud execution that does not traverse
the local machine is outside its scope.

## Architecture

```text
Claude Code/Desktop --- authenticated CONNECT ---\
Codex ------------- authenticated HTTP/SSE/WS ----> per-user Relay proxy
Hermes ---------------- authenticated CONNECT ----/        |
installed hooks -------- authenticated hook POST ----------+
                                                           |
                                   sessions + middleware + exporters
```

The service binds a discovered loopback address and stores it in protected
per-user state. It does not depend on a machine-wide fixed port, so several OS
users can enroll Relay on the same machine. Each enrollment has a distinct
stored credential. Claude Code and Claude Desktop share one effective provider
credential and corporate route because both use the same Claude settings file.

## Supported Commands

The public coding-agent lifecycle is:

```bash
nemo-relay install <claude-code|claude-desktop|codex|hermes|all>
nemo-relay uninstall <claude-code|claude-desktop|codex|hermes|all>
nemo-relay doctor <claude-code|claude-desktop|codex|hermes|all>
```

`nemo-relay claude-desktop` remains available as a protected deep-link
launcher after Claude Desktop enrollment. The `run`, `claude`, `codex`,
`hermes`, `mcp`, and standalone `serve` or default gateway launch paths are no
longer available.
