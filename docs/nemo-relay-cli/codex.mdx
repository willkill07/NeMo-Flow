Enroll Codex, then launch the Codex CLI or local app normally:

```bash
nemo-relay install codex
# Linux only: export CODEX_CA_CERTIFICATE="<path printed by install>"
codex
```

Relay retains Codex's native ChatGPT OAuth or API-key upstream routing. It
installs a managed provider alias that points to the discovered per-user
listener, sets `supports_websockets=true`, and installs the supported trusted
lifecycle hooks. It does not install a Relay MCP server.

<Note>
On Linux, Codex 0.143.0 and newer loads custom roots from
`CODEX_CA_CERTIFICATE`. Relay checks that preferred selector first. When it is
unset, Relay accepts `SSL_CERT_FILE` only when the selected bundle contains the
active Relay root. Installation writes a stable owner-only bundle and prints
its path; exporting that `CODEX_CA_CERTIFICATE` value in every environment that
launches Codex is the recommended setup. Then restart Codex. For example:

```bash
export CODEX_CA_CERTIFICATE="<path printed by nemo-relay install codex>"
codex
```

Always use the printed path because the default follows `XDG_DATA_HOME` and an
explicit `--install-dir` selects another root. Relay updates the stable bundle
during CA rotation and preserves a pre-existing
`CODEX_CA_CERTIFICATE` or `SSL_CERT_FILE` bundle inside it. Relay cannot change
the environment of an already-running shell or desktop session. `doctor`
fails until the effective Codex launch environment contains the active Relay
root.
</Note>

<Warning>
Changing the top-level Codex model provider can make existing Codex Desktop
threads appear hidden after restart. Relay does not delete those threads. Fully
quit Codex Desktop, run `nemo-relay uninstall codex`, and restart it to restore
the prior provider and thread visibility.
</Warning>

## Responses HTTP and SSE

Codex Responses requests enter the same managed-provider engine used by other
native traffic. Relay decodes them with the OpenAI Responses codec, applies
guardrails and interceptors, forwards the effective request with its provider
credentials, preserves SSE event order, and finalizes the managed call on
completion, failure, cancellation, or disconnect.

## Responses WebSockets

Each authenticated Codex WebSocket establishes an upstream OpenAI or ChatGPT
WebSocket through the Codex enrollment's corporate route. Every text
`response.create` frame is treated as one managed streaming LLM call.

Relay revalidates the live service generation and configuration fingerprint for
every `response.create`, including later calls on an already-established
socket. A changed configuration closes the connection before the next managed
call reaches the provider.

- One response can be active per connection.
- Request interceptors can rewrite the frame before upstream delivery.
- Provider JSON events retain their visible ordering.
- `response.completed`, `response.failed`, and `response.incomplete` finalize
  the call.
- Binary and malformed request frames close the connection.
- Frame size, queued writes, idle time, total duration, and concurrent sockets
  are bounded.
- Relay does not retry after the first visible provider event.

An unsupported upstream wire change produces a protocol compatibility error
instead of silently bypassing Relay.

## Local Coverage

Local CLI, local app, and background clients using the enrolled user
configuration are covered. Remote/cloud Codex tasks that do not traverse the
local proxy are not observable.

Run:

```bash
nemo-relay doctor codex
```

Doctor checks the provider alias, WebSocket capability, hooks, endpoint,
service, trust where applicable, generation, configuration identity, and
corporate proxy. On Linux it also verifies the Relay-managed Codex bundle and
the effective `CODEX_CA_CERTIFICATE` or `SSL_CERT_FILE`.

Remove the Codex-owned fields and hooks with:

```bash
nemo-relay uninstall codex
```

On Linux, apply the printed TLS cleanup before restarting Codex: remove the
Relay-managed `CODEX_CA_CERTIFICATE` value from every Codex launch environment.
If installation replaced a pre-existing `CODEX_CA_CERTIFICATE` selection, or
composed from `SSL_CERT_FILE`, uninstall prints that recorded variable and
source path so you can restore it exactly.
