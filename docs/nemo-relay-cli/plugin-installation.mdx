Persistent enrollment is the only supported coding-agent transport. It
replaces transparent wrappers, generated Relay MCP entries, MCP leases, and
standalone gateways.

## Before You Install

Close the agent being enrolled. A force reinstall or CA rotation requires all
enrolled agents to be stopped.

Linux enrollment requires a running systemd user session. The service and its
discovered loopback endpoint are user-scoped, so different users on one machine
do not share a listener, credentials, state, or trust material during normal
operation. This supports cooperative multi-user machines, not hostile tenant
isolation. The listener presents a certificate chained to the enrolled user's
owner-protected CA before a client sends credentials, so occupying a stopped
service's TCP port does not impersonate Relay. A malicious account can still
reserve candidate loopback ports and cause denial of service. Use separate
machines or an OS isolation boundary for mutually untrusted users.

On macOS, installation changes the login Keychain trust settings. On Windows,
it changes the CurrentUser Root store. Linux does not change system trust; it
writes Relay-owned agent CA bundles. For Linux Codex 0.143.0 and newer, use the
installer-printed `CODEX_CA_CERTIFICATE` setting. If that variable is unset,
Relay also accepts an existing `SSL_CERT_FILE` bundle containing the active
Relay root. Installation cannot modify an already-running shell or desktop
session. `--dry-run`, normal output, doctor, and this guide disclose the
platform-specific action. The CA is constrained to Relay's supported native
provider hosts and is removed by the final uninstall.

Inspect the planned changes without writing them:

```bash
nemo-relay install codex --dry-run
```

## Install

```bash
nemo-relay install claude-code
nemo-relay install claude-desktop
nemo-relay install codex
nemo-relay install hermes
```

Enroll detected stable CLI agents on `PATH`:

```bash
nemo-relay install all
```

Claude Desktop is a preview integration and must be selected explicitly.

Each enrollment gets a distinct stored credential, hook route, configuration
patch, and ownership record. All enrollments for one user share one discovered
loopback listener, one service, and one constrained CA. Because Claude Code
and Claude Desktop use the same Claude settings file, their provider traffic
uses one active shared Claude credential and upstream route when both are
enrolled. Relay also persists the absolute user configuration directory used at
enrollment, so launchd, systemd, and Task Scheduler do not need to inherit the
installer's `XDG_CONFIG_HOME` or equivalent shell environment.

### Nondefault state root

The coding-agent CLI option `--install-dir` selects the shared proxy-state and
marketplace root; it is separate from the bootstrap installer's binary
destination option with the same name. This override is intended for testing
and isolated environments. Use the identical root for every enrollment that
must share the proxy and for every later doctor or uninstall command:

```bash
nemo-relay install codex --install-dir /absolute/relay-test-root
# Linux only: export CODEX_CA_CERTIFICATE="<path printed by install>"
nemo-relay doctor codex --install-dir /absolute/relay-test-root
nemo-relay uninstall codex --install-dir /absolute/relay-test-root
```

Relay refuses an explicit install root when the user's proxy is active at a
different root. Doctor and uninstall likewise refuse a different explicit
root when the requested agent is enrolled at the active root. Omitting
`--install-dir` uses the persisted per-user locator.

### Claude ownership

Claude Code and Claude Desktop are tracked separately even though their
effective Claude settings overlap. Removing one cannot remove a field still
owned by the other. The shared provider route means Relay cannot reliably
attribute intercepted Claude traffic to one of the two processes.

### Codex ownership

Relay installs the managed `nemo-relay-openai` provider alias with
`supports_websockets=true`, retains ChatGPT OAuth or API-key routing, and
installs the supported trusted hooks. It does not generate an MCP entry. On
Linux, Relay maintains an owner-only stable Codex CA bundle across rotations;
the Codex launch environment should select it with the installer-printed
`CODEX_CA_CERTIFICATE` setting. If `CODEX_CA_CERTIFICATE` is unset, Relay also
accepts an existing `SSL_CERT_FILE` bundle that contains the active Relay root.

### Hermes ownership

Relay installs trusted lifecycle hooks and patches the enrolled
`$HERMES_HOME` environment for the local CLI, gateway, cron, API-server, ACP,
and desktop-backed local modes. It does not generate an MCP entry.

## Multi-user Machines

The production listener has no fixed port. Relay chooses a user-specific
candidate in `30000-49999`, probes alternatives, and falls back to an OS
allocated port. The endpoint is persisted in owner-only state and copied into
that user's generated settings. If another process wins the bind between the
probe and the first service start, Relay transactionally selects and persists
a replacement, retargets provisional Claude settings, and retries. A later
collision for an existing enrollment fails closed so Relay does not silently
invalidate installed agent configuration.

Separate OS users therefore have independent services, endpoints, credentials,
trust entries, state, and agent configuration. Do not manually share one
user's endpoint or state with another.

## Legacy Installation Block

Relay does not automatically migrate wrapper-era, MCP-gateway-era, or
branch-era Claude Desktop state. If legacy state exists, installation stops
before mutation and prints the detected path and clean-reinstall instructions.

1. Close Claude Code, Claude Desktop, Codex, Hermes, and legacy Relay gateway or
   MCP processes.
2. Run `<old-nemo-relay> uninstall all` with the old binary.
3. If the old installation included the separate Claude Desktop integration,
   run `<old-nemo-relay> uninstall claude-desktop`.
4. Verify the legacy wrapper/MCP gateway and Claude Desktop sidecar processes
   or user services have stopped, their state and locator entries are gone,
   and the old gateway health endpoint no longer responds.
5. Install the new binary.
6. Run `nemo-relay install <agent>` for the required agents.
7. On Linux, if Codex was enrolled, export the exact
   `CODEX_CA_CERTIFICATE` path printed by installation.
8. Run `nemo-relay doctor <agent>`.

There are no compatibility aliases for the removed `run`, `claude`, `codex`,
`hermes`, `mcp`, or standalone gateway commands.

## Repair

After stopping enrolled agents, repair one enrollment with:

```bash
nemo-relay install codex --force
```

Force installation rotates the enrollment generation and rewrites only
Relay-owned values. When CA rotation is required, Relay updates trust, service
state, fingerprints, and agent patches transactionally.

## Uninstall

```bash
nemo-relay uninstall codex
```

Uninstall restores matching previous values rather than deleting whole files.
If an application or user changed a Relay-owned field after installation,
Relay reports the conflict instead of overwriting it.

Use `nemo-relay uninstall all` to remove every enrollment. The final removal
stops and unregisters the service, removes the exact CA fingerprint from
macOS or Windows current-user trust, removes Linux agent-scoped CA bundles,
deletes the signer and leaf cache, and removes the protected state and locator.
On Linux, Codex uninstall also prints the exact
`CODEX_CA_CERTIFICATE` value to remove from each launch environment and the
pre-enrollment CA variable and path to restore, when one was recorded. Apply
that instruction before restarting Codex.

## Verify

```bash
nemo-relay doctor claude-code
nemo-relay doctor claude-desktop
nemo-relay doctor codex
nemo-relay doctor hermes
```

Doctor checks enrollment ownership, endpoint, service identity, generation,
trust, signer, certificate expiry, configuration fingerprint, settings, hooks,
and corporate proxy route. Hermes additionally classifies the configured base
URL as managed or hook-only/degraded without probing or naming the provider.

For Codex Desktop, enrollment changes the top-level model provider. Existing
threads can temporarily appear hidden after restart, but Relay does not delete
them. If this occurs, fully quit Codex Desktop, run `nemo-relay uninstall
codex`, and restart it to restore the prior provider and thread visibility.
