This page contains the release notes for [NVIDIA NeMo
Relay](/about-nemo-relay/overview).

## Release 0.7

NVIDIA NeMo Relay 0.7 replaces coding-agent wrapper and gateway transports
with the unified per-user proxy described below.

### Highlights

- Coding-agent integrations now use one persistent authenticated proxy per OS
  user for Claude Code/Desktop, Codex, and Hermes. The proxy supports managed
  HTTP/SSE and Codex Responses WebSockets, uses a discovered per-user loopback
  port, and replaces transparent wrappers, MCP-owned sidecars, and standalone
  coding-agent gateways.
- The first enrollment installs a constrained CA in macOS login Keychain or
  Windows CurrentUser Root trust. Linux uses an agent-scoped bundle and an
  owner-only PKCS#8 key without changing system trust.
- Claude, Codex, and Hermes enrollments have independent ownership and clean
  uninstall. Claude Code/Desktop retain distinct records but share one
  effective provider credential and route through their common settings file.
- Proxy state persists the exact user configuration directory for the login
  service. Hermes retains sanitized corporate `NO_PROXY` exclusions without
  loopback or managed-host bypasses, and Windows service ownership verifies both
  scheduled-task SID fields.

## Known Issues in 0.7

- Go and the raw C FFI remain experimental and source-first. Generated API
  pages focus on Rust, Python, and Node.js.
- Local coding-agent observability depends on host hooks and provider traffic
  reaching the authenticated per-user proxy. Relay cannot fully capture remote or cloud
  execution that bypasses the local host.
- Persistent Codex, Claude Code, and Hermes integrations use system and
  user-scoped Relay configuration. Coding-agent project `.nemo-relay`
  configuration and transparent runs are no longer supported.
- Unknown public Hermes providers reached with `CONNECT` on port 443 are
  tunneled with explicitly hook-only, degraded observability; other ports are
  rejected, and request and execution interceptors do not apply.
- TLS pinning, mandatory HTTP/2 or HTTP/3, and vendor endpoint or WebSocket
  protocol changes can make a managed provider route fail closed until Relay
  adds compatibility.
- Codex 0.143 does not expose `SessionEnd`, and Codex multi-agent v2 encrypts
  delegated-task payloads that Relay cannot decrypt or reliably link.
- Codex enrollment changes the top-level model provider and can make Desktop
  threads appear hidden after restart. The threads are not deleted; uninstall
  restores the prior provider and visibility.
- Corporate proxy preservation supports explicit HTTP(S), optional Basic
  authentication, custom CA bundles, and `NO_PROXY`. SOCKS,
  PAC/autodiscovery, NTLM, Kerberos, and platform-integrated authentication
  are not yet supported. Relay resolves provider DNS locally, requires every
  answer to be public, and sends an IP-literal `CONNECT` authority upstream;
  hostname-only ACLs and proxy-resolved-DNS deployments require adjustment.
- The Node.js binding and package workflows require Node.js 24 or later.
- Switchyard is experimental, excluded from default CLI builds, and requires a
  separately managed compatible service and a named authenticated ATOF HTTP
  stream sink.
- OpenClaw has public hook-backed telemetry. Its security and optimization
  coverage is partial because it does not own a managed execution path.
- The NeMo Guardrails remote backend inherits its configured service's
  availability, latency, and policy behavior. The local backend requires Python
  3.11 or later and `nemoguardrails==0.22.0`.
- The PII redaction plugin currently supports its deterministic local backend;
  local-model backend configuration is reserved for future work.
- Pricing and optimization estimates depend on model names, token data, pricing
  sources, and freshness evidence. Missing or inconsistent evidence produces
  partial or absent cost fields rather than zero values.
- ATOF stream sinks and remote ATIF storage require reachable, correctly
  configured destinations. A failed stream sink does not stop file output or
  other active sinks.
- ATIF omits point-in-time marks. Use ATOF for the canonical mark stream;
  OpenTelemetry and OpenInference tool-style mark projection is only a
  visualization aid.
- Native dynamic plugins run in the Relay process and are not sandboxed. A
  `grpc-v1` worker runs in a separate process, but that process is not a
  security sandbox.
- Treat Python `LLMRequest` objects as immutable. Request middleware that
  changes content must return a new request object.
- Native subscriber callbacks arrive asynchronously. Flush subscribers before
  depending on their side effects, captured events, files, or exporter output.
- Operational logging configuration and sink lifecycle are available, but broad
  operational log coverage across commands is not yet available.
